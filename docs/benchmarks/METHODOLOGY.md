# Architecture benchmarking
Pin baseline commit and common Rust core commit, lockfiles, models and decoder versions. Compare Electron/current, Electron/Rust, Tauri/Rust, GPUI/Rust. Separate OS, architecture, hardware, power mode and GPU driver. Use identical legally acquired local audio with SHA-256 manifest, identical settings and isolated copies of library/cache.
Run at least 10 repetitions per scenario (30 preferred for tail latency); randomize configuration order, record failures and raw observations. Report median and p95 (nearest-rank), never merge OS results. Cold launch after reboot or explicitly defined OS cache procedure; warm launch after clean exit; analysis cache cold/warm independently. Measure first usable frame, not process spawn alone. Collect aggregate process-tree RSS, CPU time, peak RSS, GPU activity with OS-specific instruments; report unavailable metrics as null. Measure UI input-to-present latency, waveform frame times and dropped frames during playback, zoom and analysis. Use 10/100/1000 tracks and 10000 library rows; do not claim synthetic rows are actual audio analyses. Record installer and installed bytes separately, including shared runtime assumptions.
Existing commands: npm ci; npm run test:all; npm run smoke; npm run benchmark:rhythm; npm run offset-test; npm run corpora:verify; npm run eval -- --help (inspect CLI before corpus runs).
The included architecture benchmark runner measures wall time of an arbitrary command only; it is not a desktop profiler. Each repetition launches a new process but does not evict OS caches. Build once before measurement. No audio or personal paths in committed results.
Musical gates: compare paired outputs, existing regression tests, BPM strict/half-double, key exact/weighted, beat/downbeat F-measure, grid drift, structure boundaries and blinded DJ cue review. Freeze tolerances before comparison. Preserve all exports/imports, manual edits, offsets and vocal model quality. Missing corpus audio is not a passing result.
